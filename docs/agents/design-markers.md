# 决策标记（Design Marker）判据

> 定位：写或改 `// Design(#<issue>): <决策>` 注释时的操作判据。术语定义在 `GLOSSARY.md`「治理」段；标记的**形态**由 `tests/PhotoPrivacy.IntegrationTests/DesignMarkerSourceTests.cs` 机械守住（本文件不复述正则），这里只管机器判不了的**取舍**。
> 生效：#52；守卫：#65。

## 选号：指向存续出处

标记里的号是这条决策**今天住在 tracker 的哪里**，不是"当年谁提的"。顺着号点进去要能读到这条决策现在的说法，读不到就选错了。

| 决策的来源 | 指哪张票 | 首批实例 |
| --- | --- | --- |
| 换栈主线拍的（D1–D14） | #49（spec 兼地图） | IPC 行协议唯一主缝、旧 UI 冻结 |
| 仍有一张活票在讨论它，或登记着它的未决假设 | 那张票 | `-stay_open` 的 stdin 并发假设 → #39；同用户抢先建管道未加固 → #7 |
| 决策本体还在被收敛/被裁决 | 承载收敛的那张票 | 组合根残余视图缝 → #23（随 #53 定生死） |

ADR 时代（`docs/adr/` 出仓前）的决策没有原始票：先在现存活票里找一张登记着这条决策或其假设的来指，并在正文写清残余状态（"未实测""未加固"），而不是为它新开票——凭空新开的号会变成下一个悬空引用。

## 挂哪一级

约束的是整类就挂在类型声明上，约束的是一条语句就挂在语句上方。带 `///` 文档块的声明，标记插在文档块与声明之间（守卫会红的那形态是把标记留在文档块之上）。

## 正文写什么

一句人话讲**决策本身**——被禁或被锁的行为，不是改动的来历。历史与理由留在既有注释里原地不动，标记只当可检索的锚：`Design(#39): … 禁每文件 spawn；… 未实测假设，风险登记在 #39。` 前半是决策，后半是残余状态。

## 决策只住两处

tracker 的 issue 正文，加源码里的 Design 标记——治理文件不出仓、也不进仓（`docs/adr/` 保持拆除，见 fa360d6）。

存量引用（如 `不变量①…⑤` 编号表）的批量对账归 #63；日常只给**新决策**落标记，不顺手给老代码补写。
