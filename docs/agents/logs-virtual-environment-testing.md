# #57 日志页对齐虚拟环境测试方案

> 本文档针对 [Issue #57](https://github.com/Xxx91n/photo/issues/57)「日志页对齐：审计尾巴双通道等效」提供在无实机桌面条件下的虚拟环境测试与验证方案。

## 1. 背景与现状

在 #90 的核销审计中，#57 存续以下核销状态：
1. **AC1（双通道协调）**：PR #75 已合并进入 main，本地 tail 与 IPC backfill 协调及代际隔离去重代码已就绪。
2. **AC2（滚动/浏览大批量日志不卡顿）**：此前实机目检仅小批量验证，大批量日志灌入未探活。
3. **AC3（冒烟清单日志相关项）**：E1/E2/E3/E5 已通过；E4（重启旧日志回灌）已由 #102 / #137（B′ 水位过滤方案）修复并由探针测试守护。

由于本机执行环境不具备图形桌面与本地编译能力（严格遵循 CI-only 与远端构建纪律），需寻找能提供虚拟环境来测试的办法。

## 2. 虚拟环境测试办法设计

参考 PR #168 / #32（macOS launchd 生命周期虚拟环境验证）的成功先例，虚拟环境测试依托以下通道：

### 通道 A：GitHub Actions Runner 虚拟机作为虚拟环境（推荐）
- **载体**：`.github/workflows/logs-parity-verify.yml`
- **执行方式**：在 GitHub Actions runner 虚拟机中执行远端构建与全链验证，本地零编译。
- **验证面**：
  - 自动化运行 `scripts/verify-logs-parity.sh`，生成 600+ 条大批量真实格式审计日志；
  - 验证 `MAX_LOG_ENTRIES`（500 条）截断上限、避免无限制内存消耗与列表卡顿；
  - 结合 `cargo test -p photoprivacy-logs` 断言 backfill 水位过滤、跨日轮转与代际去重逻辑；
  - 收集 summary 与 artifact 供审查与回填。

### 通道 B：无头探针与虚拟列表测量
- 结合 `uniform_list`（固定行高、虚拟滚动）和 `LogBuffer` 架构，在测试台上模拟快速滑动与过滤切换的视口渲染行切片，验证大批量日志下仅渲染可见视口行，确保 O(1) 渲染复杂度，解决卡顿隐患。
